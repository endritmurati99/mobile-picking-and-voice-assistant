## 4. R4 must not be deployed, and why

`remediation/r4-postgres` has been REJECTED twice. Its second review found two Criticals that are
settled by measurement, not opinion:

- **The branch is deployable-by-accident.** Its Compose change pointed the app services at
  `n8n_app` / `odoo_app`, roles that do not exist on the live cluster, so a stray
  `docker compose up -d` takes Odoo and n8n down. The fix round reverted the defaults to the legacy
  identity; the re-review then found the fresh-volume path re-opens the same hole.
- **The `pg_shdepend` residual-ownership check cannot fire on this cluster.** The legacy role is the
  bootstrap superuser at `pg_roles.oid = 10`, and PostgreSQL records no dependency rows for pinned
  objects. Measured: `shdepend_owner_rows_for_odoo = 0`. So `apply` reports a *verified* ownership
  transfer while proving nothing. Same measurement session: `picking_datacl = NULL`, which is why
  the rollback's GRANT-only ACL restore silently drops PUBLIC's `CONNECT`.

Fix round 2 was in flight when the session ended. **Do not merge R4 and do not let its Compose
change reach the live stack until that round is reviewed.**

## 6. Things that cost real time to learn today

- **Docker from this WSL.** Integration is OFF: the CLI is
  `/mnt/c/Program Files/Docker/Docker/resources/bin/docker.exe`, run from the project directory.
  Every path argument needs `wslpath -w`, and **exported shell variables do not reach it** without
  `WSLENV` — overrides belong in an env file. A `127.0.0.1`-bound published port is on *Windows'*
  loopback and is NOT reachable from WSL as `127.0.0.1`.
- **Caddy does not evaluate directives in file order.** It sorts by its own directive order, where
  `handle` outranks `respond`. The plan's `respond @blocked 404` above `handle @public_api` blocked
  nothing — measured: `/api/docs` served Swagger UI from uvicorn — and the plan's own test passed.
  The deny-list must be a `handle @blocked { ... }` block.
- **Starlette's `ServerErrorMiddleware` catches everything.** Raising out of an ASGI `receive` to
  enforce a body limit reaches the client as a 500, not your status. Write the 413 at the moment of
  overflow and discard what the unwinding app still sends.
- **Odoo runs REPEATABLE READ.** After a unique-violation the winner's row is invisible to this
  transaction, so re-SELECT-and-retry loops forever. Classify from the exception instead. The plan
  specified the broken shape; lane R2 had already been bitten by the same thing.
- **An internal Docker network has no egress**, and services that lazily download models die in a
  restart loop. Cache volume plus an explicit one-shot egress overlay.
- **Docker hands out the low addresses of a subnet dynamically.** A service demanding a fixed
  `172.28.10.2` fails with "Address already in use" if anything else started first — reserve the
  range with `ip_range`.
- **Subagents die** on `/mnt/c` at a 600 s stall watchdog and occasionally on API errors. Demand
  progress lines, have them write reports incrementally, and resume a dead agent from its transcript
  with SendMessage rather than restarting it.
